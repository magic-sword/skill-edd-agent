# Pythonコード設計・リファクタリング・開発スタイルガイド

## 1. モジュール分割とクリーンアーキテクチャ
* **単一責任の原則 (SRP)**: 1つのクラス・関数・モジュールに複数の責務を持たせないでください。
* **ファイルサイズの抑制**: 1ファイルが300行を超え始めたら分割を検討してください。過度な1ファイル集約はAIのスタックや文脈逸脱の原因となります。

## 2. 循環参照のスマートな回避
* パッケージ間・モジュール間の循環参照が発生した場合は、場当たり的な関数内ローカルインポートで済ませず、以下のいずれかのベストプラクティスを採用してください：
  1. インターフェースや共通データ構造を独立した低層モジュール（例: `models.py`, `types.py`）に切り出す。
  2. パッケージの `__init__.py` で `__getattr__` や遅延ロード機構をスマートに定義する。

## 3. 型定義とクラス設計
* 辞書オブジェクト (`dict`) の無秩序な引き回しを避け、型ヒント（Pydanticモデル、dataclassなど）を活用して入力・出力を明確にスキーマ化してください。
* クラス設計時はコンストラクタ (`__init__`) で不必要な重い処理（ファイルロードやネットワーク通信など）を行わず、明示的なファクトリメソッドや初期化メソッドを利用してください。
