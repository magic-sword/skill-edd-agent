# mock-executor

## 概要

指定されたスキルに対してADK評価シミュレーションを実行し、その結果を検証します。

### 主な機能
* 指定されたスキルに対するADK評価シミュレーションを実行します。
* 評価に使用するテストデータセットのパスを解決し、必要に応じてデフォルトを使用します。
* 評価設定ファイルが存在しない場合に自動生成する機能を提供します。
* 評価結果の精度を設定された閾値と比較し、合否を判定します。
* 評価の実行結果とステータスをToolContextに記録します。

### 内部処理の流れ
1. 評価対象スキルの名前が指定されているか確認します。
2. 指定されたスキル名からスキル情報を取得します。
3. 評価セットのパスを解決します（指定がなければデフォルトのトリガー評価セットを使用）。
4. 評価設定ファイルのパスを解決し、必要に応じてデフォルト設定を生成します。
5. ADK評価シミュレーションを実行します。
6. 評価結果を解析し、設定された精度閾値に基づいて合否を判定します。
7. 評価結果、ステータス、メッセージ、精度、閾値をToolContextのstateに更新します。
8. 評価が合格した場合は成功メッセージを返し、不合格の場合はエラーを発生させます。

## トリガー条件

- 「〇〇スキル」の評価を実行してください。
- 「〇〇スキル」のテストを行いたい。
- 「〇〇スキル」のADK評価シミュレーションを開始して。
- 「〇〇スキル」を「skills/my-skill/evals/trigger/eval_set.jsonl」で評価してほしい。
- 「〇〇スキル」の精度を検証してください。
- 「〇〇スキル」の動作確認をお願いします。

## AIエージェント向け使用方法

### 1. 実行手順（Instructions）

あなた（エージェント）がこのスキルをトリガーした場合は、以下の手順に従ってください。

1. 必要な入力パラメータ（`skill`など）を決定します。
2. 決定したパラメータを指定して、このスキルを起動してください。
3. 実際の処理（API呼び出しやファイル出力など）は内部スクリプト側で完結するため、あなた自身が内部テンプレートを読み込んで推論したり、成果物を手動で組み立てたりする必要はありません。

> [!NOTE]
> **`skill` パラメータの使用ガイドライン:**
> * **指定可能な指示**: 評価を実行したいスキルの名前を正確に指定してください。
> * **構造的な制約（指定不可）**: 必須項目です。既存のスキル名を指定してください。


> [!NOTE]
> **`eval_set_path` パラメータの使用ガイドライン:**
> * **指定可能な指示**: 評価に使用するテストデータセットファイルのパスを指定してください。省略した場合、対象スキルのデフォルトのトリガー評価セットが使用されます。
> * **構造的な制約（指定不可）**: ファイルパス形式で指定してください。例: 'skills/my-skill/evals/trigger/eval_set.jsonl'


### 2. 呼び出し方法
- **インプロセス呼び出し (Python API)**: ロード関数 `process_message(params, tool_context)` を使用。
- **サブプロセス呼び出し (CLI)**: CLIランナーを使用。
  `python3 -m edd_agent_tools.run mock-executor [オプション引数]`
- **出力形式 (Output Mode)**: `VALUE_ONLY` (出力は単純なプレーンテキストの値のみとなります。)

### 入力パラメータ

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| skill | str | はい | 評価対象スキルの名前またはパス。 |
| eval_set_path | str | いいえ | テストデータセットファイルのパス。 |
| config_file_path | str | いいえ | 評価設定ファイルのパス。 |
| timeout_seconds | int | いいえ | 評価のタイムアウト秒数。 |
| threshold_accuracy | float | いいえ | 合格に必要な精度の閾値（0.0 から 1.0 の浮動小数点）。デフォルトは 1.0。 *(制約: 最小値: 0.0, 最大値: 1.0)* |

### 出力値

スキル実行結果を示す単一のテキストメッセージ（プレーンテキスト）が返されます。
