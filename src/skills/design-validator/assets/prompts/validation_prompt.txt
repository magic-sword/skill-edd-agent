以下のスキル設計仕様（design.json）と、それに紐づく実装コード（models.py, handler.py, executor.py）を詳細に分析し、その整合性を評価してください。

### 評価項目
1.  **設計と入力モデルの整合性**:
    *   `design.json` の `parameters` と `models.py` の `Input` クラスが一致しているか？
    *   パラメータ名、型、必須性、説明、制約（`ge`, `le`, `min_length`, `max_length`, `pattern`, `choices`）が正しく反映されているか？
2.  **設計と出力モデルの整合性**:
    *   `design.json` の `response_parameters` と `models.py` の `Output` クラスが一致しているか？
    *   パラメータ名、型、必須性、説明、制約が正しく反映されているか？
3.  **ハンドラーの整合性**:
    *   `handler.py` の `SKILL_METADATA` が `design.json` の `name`, `description`, `summary`, `execution_type`, `output_mode` と一致しているか？
    *   `process_message` 関数が `SkillExecutor` を正しく呼び出しているか？
    *   `output_mode` に従って戻り値の形式が適切に処理されているか？
4.  **エグゼキューターの構造**:
    *   `executor.py` の `SkillExecutor` クラスが `Input` と `ToolContext` をコンストラクタで受け取っているか？
    *   `execute` メソッドが `Output` を返却するシグネチャになっているか？
    *   `execute` メソッド内でビジネスロジックが適切に分割され、責務が単一責任の原則に従っているか？（現在の実装段階では `NotImplementedError` が想定されるが、最終的な設計としては考慮対象とする）
5.  **全体的な整合性と品質**:
    *   設計と実装の間に論理的な矛盾や不足はないか？
    *   コーディング規約（Docstring、変数名など）は守られているか？
