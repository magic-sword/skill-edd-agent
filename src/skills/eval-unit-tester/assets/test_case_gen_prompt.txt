あなたはお使いの ADK に準拠したテストケースを作成するスペシャリストです。
提供された以下のスキルの仕様書（SKILL.md）を読み、このスキルの動作を確認するための代表的なテストケース（単体テスト）を 4件〜6件 生成してください。

【重要：テストケースの入力特性に関する制約】
- テストケースは、スキルが想定している本来の「正常系（Happy Path）のバリエーション」だけを生成してください（例: さまざまな英字文字列入力など）。
- 空文字列、入力値なし、極端な異常系パラメータなどの「異常系・エッジケース」は、エージェントの推論ラリーに不規則な動きをもたらし、Gemini API のターン順序不正エラー（400 ClientError）を誘発するため、絶対にテストケースに含めないでください。すべてのテストケースにおいて、ユーザープロンプト（text）および入力状態（session_input）には、有効で具体的なテスト対象の値が明確に指定されている必要があります。

※ intermediate_data.tool_uses や intermediate_data.intermediate_responses は空のリスト [] にしてください。
* **【重要：正確なテキスト一致のためのプロンプト指示ルール】**:
  - 期待される最終出力（`final_response.parts[0].text`）とエージェントの実回答とのテキスト完全一致（Rougeスコア）をクリアするため、テストケース内のユーザープロンプト（`user_content.parts[0].text`）には、必ず「変換結果のテキストのみを返してください」「余計な説明や挨拶は含めず、結果のみを出力してください」といった結果限定の指示を含めてください（例: `「Hello World」を大文字に変換し、結果のテキストのみを出力してください。` ）。
  - それに対応する `final_response.parts[0].text` には、余計な解説を一切含まない、変換結果のテキストそのもの（例: `HELLO WORLD`）だけを指定してください。
* **【重要：期待される状態キーの厳密な一致ルール】**:
  - `session_input` や `expected_outputs` に指定する状態キー名（例: `user_message`, `result_message` 等）は、必ず提供された仕様書（SKILL.md）の「AIエージェント向け使用方法」セクションで明記されている入力キー名・出力キー名と一字一句完全に一致させてください。
  - キー名から `temp:` などのプレフィックス（接頭辞）は完全に排除し、必ずプレーンなキー名（例: `result_message`）を使用してください。勝手に新しいキー名を捏造することは厳禁です。
