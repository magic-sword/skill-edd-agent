※要件詳細や既存コードを分析し、新設計モデルの各フィールドを決定してください：
1. 目的の説明（description）:
   このスキルがどのような目的・役割を持つかを、他のLLMがツールロードしてコンテキストに加えた際に無駄なスペースを圧迫しないよう、「1文で極めて端的に」説明してください（メタデータ記述用）。
2. 仕様概要（summary）:
   このスキルの本質的な目的、機能概要、提供する価値、および想定される処理の流れを要約した、簡潔な日本語の1〜2文のテキストを `summary` に設定してください。
3. 実行タイプ（execution_type）:
   以下のルールに基づいて厳密に `"tool"` または `"agent"` を選択して設定してください。
   - "agent":
     * スキルの入力パラメータに、LLMの推論を引き出して思考させるためのプロンプト用引数（`is_prompt_parameter: true` であるパラメータ、例: `prompt`, `requirement` など）が1つ以上含まれている場合。
     * スキル内部でLLM（Gemini API等）を呼び出して、テキスト生成、コード生成、設計、要約、思考推論などの創造的・非決定論的な処理を中核としている場合。
   - "tool":
     * 入力パラメータがすべて単純なデータ（ファイルパス、数値、ID、フラグ、文字列の完全一致など）のみであり、LLM用の動的なプロンプト引数（`is_prompt_parameter: true`）を一切受け取らない場合。
     * スキル内部の処理が、ファイルの保存、CLIコマンド実行、単純なデータ解決、外部通信など、100%決定論的（推論を必要とせず、常に再現性がある）なスクリプト処理のみで完結している場合。
4. 出力形式（output_mode）:
   ビジネスロジックに合致する出力形式として、`"VALUE_ONLY"`、`"CONVERSATIONAL"`、`"STRUCTURED_JSON"` の中から適したものを1つ選択してください。
5. パラメータ（parameters）: スキルが処理を実行するために受け取るべき適切なパラメータのリストを定義してください。パラメータには、名前、型、必須可否、説明に加えて、必要に応じて有効な選択肢のリスト choices（特定の選択肢のみ許可する場合）、数値の範囲制約 ge（最小値）/ le（最大値）、文字列の正規表現パターン pattern、および最小長 min_length / 最大長 max_length を設定してください。また、型が "list" の場合は要素の中身の型 items_type も指定してください。
6. 出力パラメータ（response_parameters）:
   出力形式（output_mode）が `"STRUCTURED_JSON"` の場合に限り、実行完了時に返されるJSONデータのキー構造（各キーの名前、型、説明、必須可否、および必要なら上記と同様の制約情報）を response_parameters に定義してください。出力形式が STRUCTURED_JSON 以外の場合は null または空リストを設定してください。
7. 依存関係（dependencies）: このスキルが依存する他のスキルのリストを定義してください。
8. 制約事項（constraints）:
   Pydanticモデルのモデルバリデータ（@model_validator）やフィールドバリデータ（@field_validator）、あるいは要件（プロンプト）から読み取れるパラメータの組み合わせ制約や前提条件（例: `name` と `design_path` のどちらか片方が必須であることなど）を、簡潔な日本語の制約ルールテキストのリストとして抽出し、`constraints` に設定してください。
