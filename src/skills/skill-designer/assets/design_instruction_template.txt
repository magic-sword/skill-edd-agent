=== 意味論的設計の判断ガイドライン ===
設計を行うにあたり、以下の本質的な概念の切り分けを正確に行ってください。

1. 【モジュール種別 (module_type) の判断】
   - "workflow": 複数のスキル、カスタム関数、または自律エージェントを順次実行（パイプライン接続）して1つの大きな業務を完了する場合。
   - "skill": 1つのアトミックな機能（例: ファイル操作、特定のWeb API実行など）のみを直接実行する場合。

2. 【プロンプトパラメータ (is_prompt_parameter) の判断】
   - そのパラメータの値がスキル内部の LLM のプロンプトに直接差し込まれ、非決定論的な生成や論理推論の指示テキストそのものとして利用される場合のみ `true` に設定してください。
   - ファイルパス、スキル名、秒数、判定閾値、動作モードのフラグといった、システムやプログラムが機械的に処理する引数は、文字列型であっても必ず `false` に設定してください。

3. 【ワークフローステップ (steps) の定義】
   - module_type が "workflow" の場合のみ、有向グラフとしてのステップリストを定義してください。
   - 各ステップの種別 (type) は以下を基準に選択してください：
     - "skill": 既存の登録済み別スキルを呼び出す場合。
     - "function": 決定論的な Python 処理（例: パス解決、ログ出力、API呼び出しなど）を行う場合。
     - "agent": レビューや判定など、LLM の高度な自律推論によって処理を実行する場合。

4. 【思考プロセス (rationale) の最優先記述 (CoT)】
   - JSON の最上部にある `rationale` フィールドには、他のあらゆる値を決定する前に、与えられた要件の難易度や必要な手順、そしてなぜ "skill" または "workflow" と判定したのかの設計的根拠を、必ず詳細に自己分析しながら記述してください。この思考内容（CoT）に基づいて、残りのフィールド（module_type や steps など）を整合的に決定します。
