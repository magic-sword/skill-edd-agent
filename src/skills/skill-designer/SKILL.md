# スキル仕様書: skill-designer

## 概要

自然言語の要件や既存のソースコードを基に、ADK 2.0互換のdesign.jsonを設計・生成します。これにより、新しいスキルの定義や既存スキルの再設計を効率的に行えます。

### 主な機能
* 新しいスキルを設計する
* 既存のスキルを再設計する
* 自然言語の要件や既存のソースコードを基に、ADK 2.0互換のdesign.jsonを設計・生成する
* スキルの仕様概要（summary）をユーザーの指定で上書きする

### 内部処理の流れ
1. ユーザーの要求に基づき、既存スキル名、出力ディレクトリ、ソースコードディレクトリなどのパスを解決します。
2. 再設計の場合、既存スキルの制約事項をコードベースから抽出します。
3. システムに登録されている全スキルのメタデータ（名前、トリガー条件）を収集し、ユーザーのプロンプト、既存の設計情報と共にLLMに提供し、スキルの大まかな骨組み（L1粗設計）を生成させます。
4. L1粗設計で選定された依存スキルの詳細な入出力スキーマをオンデマンドでロードし、L1の骨組みと共にLLMに提供し、各ステップの具体的な引数マッピングを含む最終的なdesign.json（L2精緻設計）を生成させます。
5. LLMが生成した設計データに対し、命名規則の自動補正やADK 2.0スキーマへの準拠バリデーションを行います。
6. 最終的に確定した設計データを指定されたディレクトリにdesign.jsonとして保存します。

## トリガー条件

このスキルは、以下の条件やプロンプトでトリガーされます。

- 「新しいスキルとして、ユーザーから与えられたテキストを要約するスキルを設計してください。入力は'text'という名前の文字列で必須、出力は要約された文字列です。実行タイプはagentにしてください。」
- 「既存のスキル`text-summarizer`に、要約の長さを指定できる`length`パラメータを追加して再設計してください。」

- 「このスキルを△△の機能を追加して更新してほしい。」

## 公開関数

### skill_designer

スキル設計要件に基づいて新しいスキルを設計し、または既存スキルを再設計するツール。

#### 実行方法

${skill_name} は、内部でLLMが自律的な**思考と推論**を行い、複雑なタスクを解決するエージェントです。このエージェントを呼び出す際は、解決したい課題を具体的に指示してください。

利用例：
${skill_name}(課題="〇〇を解決したい")

#### 入力パラメータ

| パラメータ名 | 型 | 必須 | デフォルト値 | 説明 |
|---|---|---|---|---|
| prompt | str | はい | - | 設計するスキルの機能要件や追加の改修要望を記述した自然言語のテキスト。 |
| summary | str | いいえ | - | スキルの仕様概要（ビジネス目的や要求の要約）。指定した場合、Geminiによる自動要約より優先して design.json の summary フィールドに保存されます。 |
| output_dir | str | いいえ | - | 生成されたdesign.jsonを保存するディレクトリのパス。省略時はskillから自动探索されます。 |
| skill | str | いいえ | - | 既存のスキル名。再設計時の自動探索キーとして使用されます。 |
| source_code_dir | str | いいえ | - | 再設計のベースとなる既存のスキル実装コードのディレクトリ（またはファイル）パス。指定しない場合、自動的に検出を試みます。 |


> [!NOTE]
> **`prompt` パラメータの使用ガイドライン:**
> * **指定可能な指示**: 新しく作りたいスキルの概要説明、パラメータ定義、実行タイプ（tool/agent）、制約事項などを自然言語で指示できます。また、既存コードへの機能追加要望も指定可能です。
> * **構造的な制約（指定不可）**: 設計書（design.json）の全体構造（スキーマ定義）はADK 2.0規約に基づいてバリデーションされるため、規約違反となるような無効なフィールド定義を出力させることはできません。


> [!NOTE]
> **`summary` パラメータの使用ガイドライン:**
> * **指定可能な指示**: スキルのビジネス目的や提供価値を要約した、簡潔な日本語の1〜2文を設定・上書きできます。
> * **構造的な制約（指定不可）**: 値はそのまま design.json の summary フィールドに直接流し込まれ、他の構造の生成には影響を与えません。

#### 出力仕様

* **出力モード**: `STRUCTURED_JSON`

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| status | Literal['success', 'failed'] | はい | 処理結果の成否ステータス（'success' / 'failed'） |
| message | str | はい | 処理結果のメッセージサマリー |
| output_dir | str | はい | 成果物(design.json)が格納されたスキルディレクトリの絶対パス |
