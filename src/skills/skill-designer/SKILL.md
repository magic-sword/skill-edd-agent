# skill-designer

## 概要

自然言語の要件や既存のソースコードを基に、ADK 2.0互換のdesign.jsonを設計・生成します。これにより、新しいスキルの定義や既存スキルの再設計を効率的に行えます。

### 主な機能
* 自然言語の要件からADK 2.0互換のスキル設計（design.json）を生成します。
* 既存のスキル名やソースコードを基に、その制約事項を考慮したスキルの再設計を行います。
* 生成された設計ファイル（design.json）を指定されたディレクトリに保存します。
* ユーザーが指定した要約で、生成されるdesign.jsonのsummaryフィールドを上書きできます。
* 設計プロセスにおいて、既存のソースコードやプロジェクト共通規約をLLMの推論コンテキストに自動的に含めます。

### 内部処理の流れ
1. PathResolverを使用して、既存のスキル名、出力ディレクトリ、ソースコードディレクトリなどの関連パスを解決します。
2. ConstraintParserを使用して、既存スキルの入力スキーマから制約事項を抽出し、プロンプトに含めるための文字列を生成します。
3. GeminiDesignClientを初期化し、Gemini APIとの通信準備を行います。
4. DesignPrompterを使用して、ユーザーのプロンプト、既存のスキル名、抽出された制約事項、スキャン対象のソースコード、およびプロジェクト共通規約を組み合わせて、Gemini APIへのリクエストコンテンツを構築します。
5. 構築されたリクエストコンテンツをGeminiDesignClientを介してGemini APIに送信し、ADK 2.0互換のdesign.jsonのJSON文字列を生成させます。
6. Gemini APIから返されたJSON文字列をパースし、ユーザーがsummaryを明示的に指定している場合はその値で上書きします。その後、解決された出力ディレクトリ内のassetsフォルダにdesign.jsonとして保存します。
7. 処理の成否、メッセージ、および生成されたdesign.jsonのファイルパスを含む結果を返却します。

## トリガー条件

- 新しいスキルを設計してください。
- 〇〇の機能を持つスキルをデザインしてほしい。
- 既存の〇〇スキルにこの機能を追加して再設計してください。
- この要件に基づいてスキル定義（design.json）を作成してください。
- 〇〇のスキル設計書を生成してほしい。

## AIエージェント向け使用方法

### 1. 実行手順（Instructions）

あなた（エージェント）がこのスキルをトリガーした場合は、以下の手順に従ってください。

1. 必要な入力パラメータを確認します。
2. スキル内部のテンプレート（`assets/prompt.txt` 等）をロードし、そこに記載されている指示および思考ステップに従って推論を行ってください。
3. 生成した成果物は、定義された出力形式（Output Mode）に厳密に従って出力してください。

> [!NOTE]
> **`prompt` パラメータの使用ガイドライン:**
> * **指定可能な指示**: 新しく作りたいスキルの概要説明、パラメータ定義、実行タイプ（tool/agent）、制約事項などを自然言語で指示できます。また、既存コードへの機能追加要望も指定可能です。
> * **構造的な制約（指定不可）**: 設計書（design.json）の全体構造（スキーマ定義）はADK 2.0規約に基づいてバリデーションされるため、規約違反となるような無効なフィールド定義を出力させることはできません。


> [!NOTE]
> **`summary` パラメータの使用ガイドライン:**
> * **指定可能な指示**: スキルのビジネス目的や提供価値を要約した、簡潔な日本語の1〜2文を設定・上書きできます。
> * **構造的な制約（指定不可）**: 値はそのまま design.json の summary フィールドに直接流し込まれ、他の構造の生成には影響を与えません。


### 2. 呼び出し方法
- **インプロセス呼び出し (Python API)**: ロード関数 `process_message(params, tool_context)` を使用。
- **サブプロセス呼び出し (CLI)**: CLIランナーを使用。
  `python3 -m edd_agent_tools.run skill-designer [オプション引数]`
- **出力形式 (Output Mode)**: `STRUCTURED_JSON` (特定のJSONスキーマ構造に厳密に従った構造化データを出力します。生成結果のパース成功時に生成されたファイルのパスや、エラー時にはエラーメッセージと詳細情報が含まれます。)

### 入力パラメータ

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| prompt | str | はい | 設計するスキルの機能要件や追加の改修要望を記述した自然言語のテキスト。 |
| summary | str | いいえ | スキルの仕様概要（ビジネス目的や要求の要約）。指定した場合、Geminiによる自動要約より優先して design.json の summary フィールドに保存されます。 |
| output_dir | str | いいえ | 生成されたdesign.jsonを保存するディレクトリのパス。省略時はskillから自動探索されます。 |
| skill | str | いいえ | 既存のスキル名。再設計時の自動探索キーとして使用されます。 |
| source_code_dir | str | いいえ | 再設計のベースとなる既存のスキル実装コードのディレクトリ（またはファイル）パス。指定しない場合、自動的に検出を試みます。 |

### 出力パラメータ (構造化JSONの戻り値構造)

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| status | Literal['success', 'failed'] | はい | 処理結果の成否ステータス（'success' / 'failed'） |
| message | str | はい | 処理結果のメッセージサマリー |
| output_file_path | str | はい | 生成された design.json の絶対ファイルパス |
