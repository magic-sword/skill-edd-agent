# skill-designer

## 概要

## 概要
このスキルは、Google ADK 2.0 互換の `design.json` ファイルを設計または再設計するためのツールです。AIエージェント（LLM）が直接推論するのではなく、与えられた引数に基づいてPythonスクリプトが決定論的に処理を実行し、設計ファイルを生成します。

## 主な機能と動作
このスキルは、以下のステップで動作します。

1.  **入力パラメータの取得と検証**: ユーザーから提供された機能要件 (`requirement`)、出力ディレクトリ (`output_dir`)、既存スキル名 (`name`)、および既存のソースコードディレクトリ (`source_code_dir`) を取得します。`output_dir` または `name` のいずれかが必須であり、指定がない場合はエラーとなります。

2.  **パスの解決と既存スキルの特定**: 
    *   `name` が指定されている場合、スキルレジストリから既存スキルのパスを解決し、`output_dir` や `source_code_dir` を自動的に補完します。
    *   `output_dir` が相対パスの場合、絶対パスに変換されます。
    *   既存スキル名が明示されていない場合でも、`output_dir` 内の `design.json` から読み取るか、`output_dir` のディレクトリ名から推測して特定を試みます。

3.  **既存ソースコードの収集**: 
    *   `source_code_dir` が指定されている場合、そのディレクトリ内のすべての `.py` ファイル、または指定された単一の `.py` ファイルの内容を読み込み、結合してプロンプトの一部として使用します。
    *   `source_code_dir` が指定されていない場合、`output_dir` 内の `scripts` ディレクトリを自動的に探索し、同様にソースコードを収集します。

4.  **Gemini APIへのプロンプト生成**: 
    *   内部のアセットディレクトリに保存されているプロンプトテンプレート (`prompt.txt`) を読み込みます。
    *   このテンプレートに、ユーザーが指定した機能要件 (`requirement`) と特定された既存スキル名 (`existing_name`) を埋め込み、Gemini APIに送信するメインプロンプトを生成します。
    *   収集されたソースコードは、メインプロンプトとは独立した別のコンテンツとしてGemini APIに渡されます。

5.  **Gemini APIの呼び出し**: 
    *   環境変数 `GEMINI_API_KEY` を使用してGoogle Geminiクライアントを初期化します。
    *   `gemini-2.5-flash` モデルを呼び出し、生成される `design.json` の構造が `SkillDesign` Pydantic スキーマに厳密に従うように指定します（`additionalProperties` は除去されます）。
    *   応答の多様性を抑えるため、`temperature` は `0.1` に設定されます。

6.  **設計ファイルの保存**: 
    *   Gemini APIから返されたJSONレスポンスをパースし、設計データとして抽出します。
    *   指定された `output_dir` 内に `assets` ディレクトリが存在しない場合は作成し、最終的な `design.json` ファイルを `output_dir/assets/design.json` として保存します。

7.  **ステータスの報告**: 処理の完了後、`tool_context.state` に成功メッセージと生成された `design.json` のファイルパスを設定し、結果を報告します。

## トリガー条件

- 新しいスキルを設計してください
- この要件に基づいてスキルを設計したい
- 既存のスキルを再設計してほしい
- スキル定義ファイル（design.json）を作成して
- 指定された機能要件でスキル設計を行ってください
- ソースコードを元にスキル設計を更新して

## AIエージェント向け使用方法

### 1. 実行手順（Instructions）

あなた（エージェント）がこのスキルをトリガーした場合は、以下の手順に従ってください。

1. 必要な入力パラメータ（`requirement`など）を決定します。
2. 決定したパラメータを指定して、このスキルを起動してください。
3. 実際の処理（API呼び出しやファイル出力など）は内部スクリプト側で完結するため、あなた自身が内部テンプレートを読み込んで推論したり、成果物を手動で組み立てたりする必要はありません。


### 2. 呼び出し方法

このスキルは、インプロセス（Python関数のロード）による親エージェントとのシームレスな連携、およびCLIを用いた手動での検証実行をサポートします。

#### インプロセス呼び出し (Python API)
他の親エージェントから直接ロードして呼び出す場合は、以下のインターフェースを使用します。

* **ロード関数名**: `process_message`
* **入力状態 (`tool_context.state`)**:
  * `tool_context.state["validated_input"]` に、`Input` スキーマのインスタンス（検証済みオブジェクト）が設定されます。
* **出力状態 (`tool_context.state`)**:
  * 処理結果データが状態に直接書き込まれます。

#### サブプロセス呼び出し (CLI)
* **起動方法**: `python3 -m edd_agent_tools.cli.run --skill_name skill-designer <引数>`
* **引数 (`args`)**:
  * Pydantic スキーマで定義されているパラメータをフラットなオプション引数として直接渡します（例: `--param_name value`）。

#### 出力形式の要件 (Output Mode)
- **Output Mode: STRUCTURED_JSON**
  特定のJSONスキーマ構造に厳密に従った構造化データを出力します。生成結果のパース成功時に生成されたファイルのパスや、エラー時にはエラーメッセージと詳細情報が含まれます。

### 入力パラメータ

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| requirement | str | はい | 設計するスキルの機能要件を記述した自然言語のテキスト。 |
| output_dir | str | いいえ | 生成されたdesign.jsonを保存するディレクトリのパス。省略時はnameから自動探索されます。 |
| name | str | いいえ | 既存のスキル名。再設計時の自動探索キーとして使用されます。 |
| source_code_dir | str | いいえ | 再設計のベースとなる既存のスキル実装コードのディレクトリ（またはファイル）パス。指定しない場合、自動的に検出を試みます。 |

### 制約事項

- output_dir と name のいずれか一方は必ず指定する必要があります。

### 実行例

#### 1. インプロセス呼び出し (推奨)
親エージェントが本スキルを動的ロードしてプログラムから起動する推奨コード例です。

```python
# 1. スキルのロード
skill = load_skill("skill-designer")

# 2. 状態に引数を設定して実行
# ※ 引数は validated_input 経由で process_message に渡されます
# tool_context.state["validated_input"] = Input(...)
skill.process_message(tool_context)
```

#### 2. サブプロセス呼び出し (手動テスト用 CLI)
開発環境などで本スキルを手動で動作確認する際の起動コマンド例です。

```bash
python3 -m edd_agent_tools.cli.run --skill_name skill-designer --name "target-skill-name"
```
