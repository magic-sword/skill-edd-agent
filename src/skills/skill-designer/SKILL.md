# スキル仕様書: skill-designer

## 概要

自然言語の要件や既存のソースコードを基に、ADK 2.0互換のdesign.jsonを設計・生成します。これにより、新しいスキルの定義や既存スキルの再設計を効率的に行えます。

### 主な機能
* 自然言語の要件に基づいた新しいスキルの設計と生成
* 既存のスキル定義やソースコードを基にしたスキルの再設計と更新
* ADK 2.0互換のdesign.jsonファイルの自動生成
* 生成された設計データの自動補正（クレンジング）とスキーマバリデーション
* プロジェクト全体のスキル依存関係の動的検証とフィードバック

### 内部処理の流れ
1. ユーザーの要求と提供されたパス情報（スキル名、出力ディレクトリ、ソースコードディレクトリなど）を解析し、設計対象のスキルと関連ファイルのパスを解決します。
2. 既存のスキル名が指定されている場合、そのスキルに定義されている制約事項や既存のdesign.jsonを読み込み、設計のコンテキストとして準備します。
3. システムに登録されている全スキルのメタデータ（名前、説明、入出力パラメータ）を収集し、LLMへのコンテキストとして提供します。ユーザーの要求、既存の制約、既存の設計ファイル、関連ソースコード、およびプロジェクト共通の開発規約を基に、LLMにスキルの骨組み（名前、説明、モジュールタイプ、主要パラメータ、依存関係、制約）を生成させます。
4. L1で生成された骨組み設計を基に、LLMに対してより詳細なパラメータ定義（型、必須/任意、説明など）や応答パラメータ構造を精緻化させ、最終的なdesign.jsonの内容を生成させます。
5. LLMが生成した設計データに対し、命名規則の統一やモジュールタイプの自動調整などのクレンジング処理を適用します。その後、ADK 2.0のスキーマ（ModuleDesign）に厳密に準拠しているかバリデーションを行います。
6. バリデーションに成功した設計データをdesign.jsonとして指定されたディレクトリに保存します。保存後、プロジェクト全体のスキル依存関係（欠落や循環参照）を動的に検証し、問題があれば警告をフィードバックします。
7. 設計処理の成否、生成されたdesign.jsonのパス、および関連するメッセージをユーザーに報告します。

## トリガー条件

このスキルは、以下の条件やプロンプトでトリガーされます。

- 新しいスキルとして、ユーザーから与えられたテキストを要約するスキルを設計してください。入力は'text'という名前の文字列で必須、出力は要約された文字列です。実行タイプはagentにしてください。
- 既存のtext-summarizerスキルに、要約の長さを指定するlengthパラメータを追加して再設計してください。
- 特定のディレクトリにあるPythonコードを基に、新しいmy-custom-toolスキルを設計してください。
- ADK 2.0の仕様に準拠したdesign.jsonを作成したい。

## 公開関数

### skill_designer

スキル設計要件に基づいて新しいスキルを設計し、または既存スキルを再設計するツール。

#### 実行方法
${skill_name} は、内部でLLMが自律的な**思考と推論**を行い、複雑なタスクを解決するエージェントです。このエージェントを呼び出す際は、解決したい課題を具体的に指示してください。

利用例：
${skill_name}(課題="〇〇を解決したい")

#### 入力パラメータ
| パラメータ名 | 型 | 必須 | デフォルト値 | 説明 |
|---|---|---|---|---|
| prompt | str | はい | - | 設計するスキルの機能要件や追加の改修要望を記述した自然言語のテキスト。 |
| summary | str | いいえ | - | スキルの仕様概要（ビジネス目的や要求の要約）。指定した場合、Geminiによる自動要約より優先して design.json の summary フィールドに保存されます。 |
| output_dir | str | いいえ | - | 生成されたdesign.jsonを保存するディレクトリのパス。省略時はskillから自动探索されます。 |
| skill | str | いいえ | - | 既存のスキル名。再設計時の自動探索キーとして使用されます。 |
| source_code_dir | str | いいえ | - | 再設計のベースとなる既存のスキル実装コードのディレクトリ（またはファイル）パス。指定しない場合、自動的に検出を試みます。 |
| target_entry | str | いいえ | - | 新規スキル開発時の優先的配置先エントリーの論理名（別名）。 |


> [!NOTE]
> **`summary` パラメータの使用ガイドライン:**
> * **指定可能な指示**: スキルのビジネス目的や提供価値を要約した、簡潔な日本語の1〜2文を設定・上書きできます。
> * **構造的な制約（指定不可）**: 値はそのまま design.json の summary フィールドに直接流し込まれ、他の構造の生成には影響を与えません。


#### 出力仕様
* **出力モード**: `STRUCTURED_JSON`

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| status | Literal['success', 'failed'] | はい | 処理結果の成否ステータス（'success' / 'failed'） |
| message | str | はい | 処理結果のメッセージサマリー |
| output_dir | str | はい | 成果物(design.json)が格納されたスキルディレクトリの絶対パス |
| design_path | str | はい | 生成された design.json の絶対パス |
