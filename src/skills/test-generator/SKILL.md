# スキル仕様書: test-generator

## 概要

指定されたスキルとテストタイプに基づき、対応するテスト生成スキルを動的にロードし、テストケースを生成してファイルに書き出すワークフロー。

### 主な機能
* 指定されたスキルとテストタイプに基づいて、適切なテスト生成スキルを動的にロードします。
* ロードしたテスト生成スキルを利用して、テストケースを生成します。
* 生成されたテストケースをJSONファイルとして指定されたディレクトリ（tests/）に書き出します。
* テスト生成処理の成否、サマリーメッセージ、および生成されたファイルのパスを報告します。

### 内部処理の流れ
1. ユーザーから対象スキル名 (`skill`) とテストタイプ (`test_type`) を受け取ります。
2. 指定された `test_type` に基づいて、対応するテスト生成スキル名（例: `trigger` の場合は `trigger-test-generator`）を決定します。
3. 決定したテスト生成スキルを `SkillsState` から動的にロードします。
4. ロードしたテスト生成スキルの `generate_tests` メソッドを呼び出し、テストケースデータを生成させます。
5. 生成されたテストケースデータを、`tests/{対象スキル名}/{テストタイプ}.evalset.json` のパスにJSONファイルとして書き出します。
6. テスト生成とファイル書き込みの成否に応じて、成功または失敗のステータス、処理メッセージ、および生成されたファイルの絶対パスを返します。
7. スキルロード、メソッド呼び出し、ファイル書き込み中に発生したエラーを適切に捕捉し、失敗ステータスとエラーメッセージを報告します。

## 公開関数

### generate_test_cases

指定されたスキルとテストタイプに基づき、対応するテスト生成スキルを動的にロードし、テストケースを生成してファイルに書き出します。

#### 実行方法
${skill_name} は、内部でLLMが自律的な**思考と推論**を行い、複雑なタスクを解決するエージェントです。このエージェントを呼び出す際は、解決したい課題を具体的に指示してください。

利用例：
${skill_name}(課題="〇〇を解決したい")

#### 入力パラメータ
| パラメータ名 | 型 | 必須 | デフォルト値 | 説明 |
|---|---|---|---|---|
| skill | str | はい | - | テストケースを生成する対象のスキル名。 |
| test_type | Literal['trigger'] | はい | - | 生成するテストケースの種別（例: 'trigger', 'unit', 'integration'）。 |


#### 出力仕様
* **出力モード**: `STRUCTURED_JSON`

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| status | Literal['success', 'failed'] | はい | テスト生成の成否 ('success' または 'failed')。 |
| message | str | はい | テスト生成処理のサマリーメッセージ。 |
| eval_set_path | str | はい | 生成されたテストケースJSONファイルの絶対パス。 |
