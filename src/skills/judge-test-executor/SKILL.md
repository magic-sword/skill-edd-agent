# スキル仕様書: judge-test-executor

## 概要

指定されたスキルをサンドボックス環境で実行し、LLM-as-Judgeを用いてルーブリック評価を行うテスト実行スキル。

### 主な機能
* サンドボックス環境（LocalWorkspaceEnv）でのスキル実行と出力取得。
* LLM-as-Judgeを用いた多角的なルーブリック評価の実施。
* 各テストケースの出力に対する0〜10点での詳細な採点。
* テスト結果の合格/不合格判定と全体的な合格率の算出。
* 詳細なテスト結果をJSONファイルとして出力。

### 内部処理の流れ
1. 指定された`eval_set_path`からルーブリック評価セットJSONファイルをサンドボックス環境（`env`）を介して読み込み、パースする。
2. `skill_name`に基づいてテスト対象のスキルモジュールをロードする。
3. 評価セット内の各テストケースについて、入力引数を型変換し、サンドボックス環境（`env`）内でテスト対象スキルの関数を実行して出力を取得する。
4. 取得した出力、入力引数、およびルーブリック項目に基づき、LLM-as-Judge用のプロンプトを構築する。
5. Geminiクライアントを介してLLM-as-Judgeを呼び出し、各ルーブリック項目に対する採点と合否判定を構造化された形式で取得する。
6. LLMの判定結果に基づき、テストケースの合否を記録し、全体の合格数、不合格数、合計数、合格率を算出する。
7. 詳細なテスト結果をJSON形式で整形し、サンドボックス環境（`env`）を介してファイルとして保存する。
8. 最終的なテスト結果（合格数、不合格数、合計数、合格率、詳細結果ファイルパス）を返す。

## 公開関数

### execute_judge_test

LocalWorkspaceEnv上でスキルを実行し、得られた出力を各テストケースの複数ルーブリック項目に沿って採点LLMで多角的に採点（0〜10点）し、合格判定をアサートします。

#### 実行方法
${skill_name} は、与えられたパラメータに基づいて特定のタスクを**決定論的に実行**するツールです。LLMが推論を挟まず、直接このツールを呼び出して指示通りの操作を行います。

利用例：
${skill_name}(`skill_name`, `eval_set_path`, `env`)

#### 入力パラメータ
| パラメータ名 | 型 | 必須 | デフォルト値 | 説明 |
|---|---|---|---|---|
| skill_name | str | はい | - | テスト対象のスキル名。 |
| eval_set_path | str | はい | - | ルーブリック評価セットが記述されたJSONファイルの絶対パス。 |
| env | object | はい | - | テストを実行するサンドボックス環境（WorkspaceEnvProtocol）。システムによって自動的に注入されます。 |


#### 出力仕様
* **出力モード**: `STRUCTURED_JSON`

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| passed | int | はい | 合格したテストケースの数。 *(制約: 最小値: 0.0)* |
| failed | int | はい | 不合格だったテストケースの数。 *(制約: 最小値: 0.0)* |
| total | int | はい | 実行されたテストケースの総数。 *(制約: 最小値: 0.0)* |
| accuracy | float | はい | テストの合格率（0.0〜1.0）。 *(制約: 最小値: 0.0, 最大値: 1.0)* |
| detail_file_path | str | いいえ | 詳細なテスト結果が保存されたファイルのパス。 *(制約: 最小長: 1)* |

### 制約事項

- このスキルはLocalWorkspaceEnv上で実行されることを前提とします。
- 採点にはLLMが使用されるため、LLM APIへのアクセスが必要です。
- 評価セットファイル（eval_set_path）は、judge-test-generatorスキルによって生成された形式に準拠している必要があります。
