# Test Types Design Guide

本ドキュメントは、自己進化型 EDD エージェントにおける6大テストパターンの設計仕様を定義したものです。

## 1. トリガーテスト (Trigger Testing)
- **目的**: ユーザーの自然言語発話に対するインテント分類精度（発火判定）を検証。
- **データ構造**: `positive_prompts`（正例発話）と `negative_prompts`（負例発話）。
- **判定基準**: 正例では対象スキルが選択され、負例では選択されないこと（精度 ≥ 90%）。

## 2. 契約テスト (Contract Testing)
- **目的**: 公開スクリプトの関数インターフェース、型、入力バリデーション、例外処理を検証。
- **データ構造**: 引数辞書 `inputs`、期待される戻り値ステータス `expected_status`、アサーション辞書 `assertions`。
- **判定基準**: 正常系・異常系ともに 100% 合格すること。

## 3. ゴールデンテスト (Golden Testing)
- **目的**: エージェントが生成した出力成果物が、ドメイン標準のゴールデン出力と意味的に合致するか検証。
- **データ構造**: 入力シナリオ `input_scenario` と期待出力に含まれるべき要素 `expected_outputs`。

## 4. ルーブリックジャッジテスト (Judge Testing)
- **目的**: LLM-as-a-Judge を用いて、定性的な品質（文体、構成、美しさ等）を重み付き多軸評価。
- **データ構造**: 評価シナリオ、採点項目（Criterion）、重み（Weight）、合格閾値。

## 5. 推論軌跡テスト (Trajectory Testing)
- **目的**: 複数ステップの思考プロセスにおいて、意図通りのツール呼び出し順序（ToolCall Sequence）が実行されたかを検証。

## 6. 敵対的テスト (Adversarial Testing)
- **目的**: プロンプトインジェクション、不正な型、極端な長文、リソース枯渇などの敵対的入力に対する耐性を検証。
