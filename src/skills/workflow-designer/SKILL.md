# スキル仕様書: workflow-designer

## 概要

既存スキルの入出力型仕様をスキャンし、それらを接続したワークフロー（design.json）を設計します。

### 主な機能
* ユーザーの要件に基づき、既存スキルを組み合わせたワークフロー設計書（design.json）を自動生成します。
* 既存スキルの入出力型仕様をスキャンし、それらを適切に接続するパイプライン形式のワークフローを設計します。
* 生成された設計書は、ADK 2.0互換の形式で出力されます。

### 内部処理の流れ
1. **パス解決**: 新規ワークフローの出力先ディレクトリとスキルディレクトリを決定します。
2. **既存スキル情報の収集 (L1コンテキスト)**: システム内の全ての既存スキルをスキャンし、それぞれのスキル名と概要を抽出し、ワークフローの粗設計（L1）のためのコンテキストとして準備します。
3. **L1粗設計の生成**: ユーザーの要求と収集した既存スキル情報に基づき、LLMを用いてワークフローの骨組み（ステップの順序、使用するスキル名など）を生成します。この段階では、詳細な引数マッピングは考慮しません。
4. **依存スキル詳細情報の収集 (L2コンテキスト)**: L1で生成された骨組み設計で選択された各スキルについて、その詳細な入出力パラメータ仕様を動的に取得し、精緻化設計（L2）のためのコンテキストとして準備します。
5. **L2精緻化設計の生成**: L1の骨組み設計と、収集した依存スキルの詳細情報に基づき、LLMを用いて各ステップの詳細な引数マッピングを含む最終的なワークフロー設計を生成します。
6. **設計データのクレンジングとバリデーション**: 生成された設計データに対して、命名規則の自動補正（クレンジング）を行い、ADK 2.0のワークフロー設計スキーマに準拠しているかバリデーションします。
7. **設計書の保存**: バリデーションが成功した最終設計データを、指定されたパスに design.json として保存します。

## 公開関数

### workflow_designer

ワークフロー要件に基づいて新しいワークフローを設計します。

#### 実行方法
${skill_name} は、内部でLLMが自律的な**思考と推論**を行い、複雑なタスクを解決するエージェントです。このエージェントを呼び出す際は、解決したい課題を具体的に指示してください。

利用例：
${skill_name}(課題="〇〇を解決したい")

#### 入力パラメータ
| パラメータ名 | 型 | 必須 | デフォルト値 | 説明 |
|---|---|---|---|---|
| prompt | str | はい | - | 設計するワークフローの機能要件やフローの追加要望を記述した自然言語のテキスト。 |
| summary | str | いいえ | - | ワークフローの仕様概要。指定した場合、自動要約より優先して design.json の summary フィールドに保存されます。 |
| output_dir | str | いいえ | - | 生成されたdesign.jsonを保存するディレクトリのパス。 |
| target_entry | str | いいえ | - | 新規ワークフロー開発時の優先的配置先エントリーの論理名。 |


> [!NOTE]
> **`summary` パラメータの使用ガイドライン:**
> * **指定可能な指示**: 指示トーンや特別に盛り込んでほしい仕様コンテキストの指定。
> * **構造的な制約（指定不可）**: 出力ドキュメント全体のレイアウト構成・見出し等の構造変更は不可。


#### 出力仕様
* **出力モード**: `STRUCTURED_JSON`

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| status | str | はい | 処理結果の成否ステータス（'success' / 'failed'） |
| message | str | はい | 処理結果のメッセージサマリー |
| output_dir | str | はい | 成果物が格納されたディレクトリの絶対パス |
| design_path | str | はい | 生成された design.json の絶対パス |
