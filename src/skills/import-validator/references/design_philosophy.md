# テスト自動化の分割設計思想 (Two-Phase Unit Testing Philosophy)

本プロジェクトでは、スキルの品質保証（Unit Test）を以下の「自動実行と判定が極めて容易な2つのフェーズ」に意図的に分割しています。

## 1. 分割の背景と目的

従来の pytest 等を用いたシミュレーションテストは、ユーザー入出力の揺らぎや中間状態の多様性により、判定ロジックの自動生成が難しく、実行コスト（時間・トークン）も膨大になる課題がありました。
そこで、テストの関心を「システム的動作保証」と「仕様整合性保証」に明確に分離し、それぞれを軽量なツールとして自動化しました。

## 2. 2段階テストの構成

### 第1フェーズ: システムロード検証 (System-Level Import Validation)
*   **担当ツール**: `import-validator`
*   **検証内容**: 該当スキルが Python ランタイム上で文法エラーや循環インポートエラーを起こすことなく、動的にインポート（`load_module()`）できるか。
*   **特性**: LLM非依存（数ミリ秒で完結）。構文エラーなどのイージーミスを最速で弾く CI ゲートとして機能します。

### 第2フェーズ: 設計整合性監査 (LLM-as-Judge Alignment Validation)
*   **担当ツール**: `design-validator`
*   **検証内容**: 生成されたコード（`models.py`, `handler.py`, `executor.py`）が、仕様設計書（`design.json`）で定義されたパラメータ、応答の型、および要件を満たしているか。
*   **特性**: LLM (Gemini) の構造化出力を活用し、コードの意図と設計のズレ（Pydanticモデルの定義漏れや潜在的なバグなど）を自律的に監査して 0.0〜1.0 のスコアで定量評価します。

## 3. このアプローチによるメリット

*   **Self-Improving Loop の高速化**:
    自動コード生成エージェントがバグのあるコードを書き出した際、重たい実行シミュレーションを回すことなく、この2つの超軽量テストによって「ミリ秒〜数秒」でバグを検知し、瞬時に自己修正ループへフィードバックできます。
*   **CI実行コストの最小化**:
    トークン消費を抑え、決定論的かつ予測可能なテストカバレッジを提供します。
