# skill-spec-writer

## 概要

このスキルは、Google ADK 2.0 の仕様に準拠した SKILL.md ドキュメントを自動生成するための決定論的なスクリプト処理ツールです。開発者がスキル設計（design.json）と実装コードに基づいて、人間が理解しやすい概要やトリガー条件を含む詳細な仕様書を効率的に作成できるよう設計されています。

主な機能と内部処理:
本スキルは、以下のステップで動作し、引数を受け取ってPythonコードが処理を完結させます。

*   入力パラメータの解析とパス解決:
    *   対象となるスキル名（name）または design.json ファイルへの直接パス（design_path）を受け取ります。これらのうち少なくとも一方は必須です。
    *   指定された情報に基づいて、スキル設計ファイル、出力先ディレクトリ、および実装ソースコードのディレクトリパスを自動的に解決します。
*   スキル設計情報のロード:
    *   解決された design.json ファイルを読み込み、Pydantic モデル SkillDesign に従ってその内容を検証・ロードします。これにより、スキルのパラメータ、依存関係、実行タイプなどの構造化された設計情報を取得します。
*   実装ソースコードの収集:
    *   指定されたソースコードディレクトリ（または自動解決されたスキルの scripts ディレクトリ）内のすべてのPythonファイルをスキャンし、その内容を結合して分析用の単一の文字列として準備します。これにより、スキルの具体的な動作やロジックを把握するための情報源とします。
*   LLMによる人間向け説明の生成:
    *   スキル設計情報と収集されたソースコードを基に、Google Gemini API を利用して、人間向けの「概要（human_overview）」と「トリガー条件（trigger_conditions）」を生成します。この部分は、AIエージェントがスキルを適切に利用するための自然言語による説明を生成する非決定論的な処理です。
*   Markdownドキュメントのレンダリングと保存:
    *   LLMによって生成された情報と、スキル名、機械的な説明、パラメータテーブル、出力モードの説明、実行方法などの決定論的な情報を組み合わせて、最終的な SKILL.md ファイルをMarkdown形式でレンダリングします。
    *   生成された SKILL.md は、指定された出力ディレクトリに保存され、そのパスが結果として返されます。

このツールを利用することで、開発者は手動でのドキュメント作成の手間を大幅に削減し、常に最新かつ正確なスキル仕様書を維持することが可能になります。

## トリガー条件

- スキルの仕様書を生成してほしい
- SKILL.md を作成してください
- このスキルのドキュメントを書いて
- design.json からスキル仕様書を生成して
- skill-spec-writer の仕様書を更新したい
- スキルの設計書を自動生成して

## AIエージェント向け使用方法

### 1. 実行手順（Instructions）

あなた（エージェント）がこのスキルをトリガーした場合は、以下の手順に従ってください。

1. 必要な入力パラメータ（パラメータなど）を決定します。
2. 決定したパラメータを指定して、このスキルを起動してください。
3. 実際の処理（API呼び出しやファイル出力など）は内部スクリプト側で完結するため、あなた自身が内部テンプレートを読み込んで推論したり、成果物を手動で組み立てたりする必要はありません。


### 2. 呼び出し方法

このスキルは、インプロセス（Python関数のロード）による親エージェントとのシームレスな連携、およびCLIを用いた手動での検証実行をサポートします。

#### インプロセス呼び出し (Python API)
他の親エージェントから直接ロードして呼び出す場合は、以下のインターフェースを使用します。

* **ロード関数名**: `process_message`
* **入力状態 (`tool_context.state`)**:
  * `tool_context.state["validated_input"]` に、`Input` スキーマのインスタンス（検証済みオブジェクト）が設定されます。
* **出力状態 (`tool_context.state`)**:
  * 処理結果データが状態に直接書き込まれます。

#### サブプロセス呼び出し (CLI)
* **起動方法**: `python3 -m edd_agent_tools.cli.run --skill_name skill-spec-writer <引数>`
* **引数 (`args`)**:
  * Pydantic スキーマで定義されているパラメータをフラットなオプション引数として直接渡します（例: `--param_name value`）。

#### 出力形式の要件 (Output Mode)
- **Output Mode: VALUE_ONLY**
  出力は単純なプレーンテキストの値のみとなります。

### 入力パラメータ

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| design_path | str | いいえ | design.json ファイルの直接のパス。省略された場合は name から自動探索します。 |
| name | str | いいえ | 対象の既存スキル名。design_path 省略時の自動探索キーとして使用されます。 |
| output_dir | str | いいえ | 生成されたSKILL.mdを保存するディレクトリのパス。省略時は対象スキルのディレクトリに出力されます。 |
| source_code_dir | str | いいえ | 実装ソースコードが格納されたディレクトリパス（または単一ファイル）。指定しない場合、自動的にスキルの scripts ディレクトリを探索します。 |

### 制約事項

- name と design_path のいずれか一方は必ず指定する必要があります。

### 実行例

#### 1. インプロセス呼び出し (推奨)
親エージェントが本スキルを動的ロードしてプログラムから起動する推奨コード例です。

```python
# 1. スキルのロード
skill = load_skill("skill-spec-writer")

# 2. 状態に引数を設定して実行
# ※ 引数は validated_input 経由で process_message に渡されます
# tool_context.state["validated_input"] = Input(...)
skill.process_message(tool_context)
```

#### 2. サブプロセス呼び出し (手動テスト用 CLI)
開発環境などで本スキルを手動で動作確認する際の起動コマンド例です。

```bash
python3 -m edd_agent_tools.cli.run --skill_name skill-spec-writer --name "target-skill-name"
```
