# skill-spec-writer

## 概要

このスキルは、Google ADK 2.0 互換の SKILL.md 仕様書を自動生成するためのツールです。開発者がスキル設計情報（design.json）と実装コードを提供するだけで、人間が理解しやすい概要やトリガー条件を含む詳細なドキュメントを自動的に作成します。AIエージェント（LLM）が推論するのではなく、引数を受け取ってPythonコードが処理を完結させる決定論的なスクリプト処理を行います。

主な機能と動作は以下の通りです。
-   **設計情報のロードと解析**: 指定された `design_path`（design.json ファイルの直接パス）、または `name` から自動探索された design.json をロードし、スキル名、説明、パラメータ、依存関係などの設計情報を解析します。
-   **Pydanticスキーマからの制約抽出**: 対象スキルの `handler.py` に定義された Pydantic `Input` スキーマを動的に解析し、入力パラメータのバリデーション制約（例: `Field` の `description` や `model_validator`）を自動的に抽出し、SKILL.md の「制約事項」セクションに含めます。
-   **ソースコードの読み込み**: `source_code_dir` で指定されたディレクトリ内のすべての Python ファイル、または単一のソースコードファイルを結合して読み込みます。これにより、LLMが実装の詳細を理解し、より正確な説明を生成するためのコンテキストを提供します。
-   **LLMによる概要とトリガー条件の生成**: 読み込んだ設計情報とソースコードに基づき、Gemini API を利用して、スキルが提供する機能の人間向け概要 (`human_overview`) と、スキルをトリガーするための具体的なプロンプト例 (`trigger_conditions`) を生成します。
-   **Markdownドキュメントの構築**: LLMが生成した内容と、設計パラメータから得られる決定論的な情報（パラメータテーブル、実行方法、出力モードの説明など）を組み合わせて、最終的な SKILL.md ファイルを構築します。
-   **出力**: 生成された SKILL.md は、`output_dir` で指定されたディレクトリ、または対象スキルのルートディレクトリに保存されます。

このツールは、開発者が手動でドキュメントを作成する手間を省き、常に最新かつ正確なスキル仕様書を維持するのに役立ちます。

## トリガー条件

- スキル仕様書を生成してほしい
- このスキルの SKILL.md を作成してください
- design.json を元にドキュメントを出力して
- 指定したスキルの仕様書を自動生成して
- SKILL.md ファイルを更新したい
- スキル定義ドキュメントを作成して

## AIエージェント向け使用方法

### 1. 実行手順（Instructions）

あなた（エージェント）がこのスキルをトリガーした場合は、以下の手順に従ってください。

1. 必要な入力パラメータ（パラメータなど）を決定します。
2. 決定したパラメータを指定して、このスキルを起動してください。
3. 実際の処理（API呼び出しやファイル出力など）は内部スクリプト側で完結するため、あなた自身が内部テンプレートを読み込んで推論したり、成果物を手動で組み立てたりする必要はありません。


### 2. 呼び出し方法

このスキルは、インプロセス（Python関数のロード）による親エージェントとのシームレスな連携、およびCLIを用いた手動での検証実行をサポートします。

#### インプロセス呼び出し (Python API)
他の親エージェントから直接ロードして呼び出す場合は、以下のインターフェースを使用します。

* **ロード関数名**: `process_message`
* **入力状態 (`tool_context.state`)**:
  * `tool_context.state["validated_input"]` に、`Input` スキーマのインスタンス（検証済みオブジェクト）が設定されます。
* **出力状態 (`tool_context.state`)**:
  * 処理結果データが状態に直接書き込まれます。

#### サブプロセス呼び出し (CLI)
* **起動方法**: `python3 -m edd_agent_tools.cli.run --skill_name skill-spec-writer <引数>`
* **引数 (`args`)**:
  * Pydantic スキーマで定義されているパラメータをフラットなオプション引数として直接渡します（例: `--param_name value`）。

#### 出力形式の要件 (Output Mode)
- **Output Mode: VALUE_ONLY**
  出力は単純なプレーンテキストの値のみとなります。

### 入力パラメータ

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| design_path | str | いいえ | design.json ファイルの直接のパス。省略された場合は name から自動探索します。 |
| name | str | いいえ | 対象の既存スキル名。design_path 省略時の自動探索キーとして使用されます。 |
| output_dir | str | いいえ | 生成されたSKILL.mdを保存するディレクトリのパス。省略時は対象スキルのディレクトリに出力されます。 |
| source_code_dir | str | いいえ | 実装ソースコードが格納されたディレクトリパス（または単一ファイル）。指定しない場合、自動的にスキルの scripts ディレクトリを探索します。 |

### 制約事項

- name と design_path のいずれか一方は必ず指定する必要があります。

### 実行例

#### 1. インプロセス呼び出し (推奨)
親エージェントが本スキルを動的ロードしてプログラムから起動する推奨コード例です。

```python
# 1. スキルのロード
skill = load_skill("skill-spec-writer")

# 2. 状態に引数を設定して実行
# ※ 引数は validated_input 経由で process_message に渡されます
# tool_context.state["validated_input"] = Input(...)
skill.process_message(tool_context)
```

#### 2. サブプロセス呼び出し (手動テスト用 CLI)
開発環境などで本スキルを手動で動作確認する際の起動コマンド例です。

```bash
python3 -m edd_agent_tools.cli.run --skill_name skill-spec-writer --name "target-skill-name"
```
