# skill-spec-writer

## 概要

このスキルは、Google ADK 2.0 互換のスキル仕様書（SKILL.md）を自動生成するためのツールです。開発者が既存のスキル名または設計ファイルパスを指定することで、そのスキルの設計情報（Pydanticスキーマ、パラメータ、依存関係など）と実装コードを解析し、詳細なドキュメントを生成します。

このツールの主な機能と内部処理の流れは以下の通りです。

*   **入力パラメータの受付:**
    *   `name`: 対象となる既存スキルの名前。
    *   `design_path`: 対象スキルの `design.json` ファイルへの直接パス。
    *   `output_dir`: 生成された `SKILL.md` を保存するディレクトリのパス。
    *   `source_code_dir`: スキルの実装ソースコードが格納されたディレクトリのパス。
    これらのパラメータは、AIエージェント（LLM）からの引数として受け取られ、Pythonスクリプトによって処理されます。

*   **設計情報のロードと解析:**
    入力された `name` または `design_path` に基づいて、対象スキルのディレクトリを特定し、`design.json` ファイルから設計データ（`SkillDesign`）をロードします。このデータには、スキルの `execution_type`（例: `tool` または `agent`）、定義されているパラメータ、依存関係などが含まれます。

*   **仕様書ライターの動的選択とプロンプト構築:**
    ロードされた設計データの `execution_type` に応じて、適切な仕様書ライター（`ToolSpecWriter` または `AgentSpecWriter`）が動的に選択されます。このライターは、LLM（Gemini API）に渡すための詳細なプロンプトを構築します。プロンプトには、スキルの設計パラメータ、依存関係、および解析対象のPython実装コードが含められます。

*   **LLMによる非決定論的情報の抽出:**
    構築されたプロンプトと、必要に応じて添付されたソースコードをGemini APIに送信します。LLMはこれを解析し、スキルの人間向け概要（`human_overview`）や、スキルがトリガーされる具体的な条件（`trigger_conditions`）といった非決定論的な情報を、定義されたPydanticスキーマ（`SkillTextParts`）に従った構造化JSON形式で抽出します。

*   **Markdownドキュメントの生成と保存:**
    LLMから抽出された情報と、スキルの決定論的な設計情報（パラメータテーブル、実行方法、出力モードの説明など）を組み合わせて、`SKILL.md` ファイルをMarkdown形式でレンダリングします。最終的に、指定された `output_dir` に `SKILL.md` を保存し、そのパスを返します。

このスキルは、AIエージェントが直接推論してドキュメントを作成するのではなく、引数を受け取ってPythonスクリプトが処理を完結させる「ツール」として機能します。これにより、一貫性のある高品質なスキル仕様書を自動的に生成し、開発者のドキュメント作成負担を大幅に軽減します。

## トリガー条件

- スキルの仕様書を生成してください
- ADK 2.0のSKILL.mdを作成してほしい
- 〇〇（スキル名）のドキュメントを生成して
- このスキルの設計書を出力してください
- スキルの説明ファイルを生成してほしい
- SKILL.mdを自動作成してほしい

## AIエージェント向け使用方法

### 1. 実行手順（Instructions）

あなた（エージェント）がこのスキルをトリガーした場合は、以下の手順に従ってください。

1. 必要な入力パラメータ（パラメータなど）を決定します。
2. 決定したパラメータを指定して、このスキルを起動してください。
3. 実際の処理（API呼び出しやファイル出力など）は内部スクリプト側で完結するため、あなた自身が内部テンプレートを読み込んで推論したり、成果物を手動で組み立てたりする必要はありません。


### 2. 呼び出し方法

このスキルは、インプロセス（Python関数のロード）による親エージェントとのシームレスな連携、およびCLIを用いた手動での検証実行をサポートします。

#### インプロセス呼び出し (Python API)
他の親エージェントから直接ロードして呼び出す場合は、以下のインターフェースを使用します。

* **ロード関数名**: `process_message`
* **入力状態 (`tool_context.state`)**:
  * `tool_context.state["validated_input"]` に、`Input` スキーマのインスタンス（検証済みオブジェクト）が設定されます。
* **出力状態 (`tool_context.state`)**:
  * 処理結果データが状態に直接書き込まれます。

#### サブプロセス呼び出し (CLI)
* **起動方法**: `python3 -m edd_agent_tools.cli.run --skill_name skill-spec-writer <引数>`
* **引数 (`args`)**:
  * Pydantic スキーマで定義されているパラメータをフラットなオプション引数として直接渡します（例: `--param_name value`）。

#### 出力形式の要件 (Output Mode)
- **Output Mode: STRUCTURED_JSON**
  特定のJSONスキーマ構造に厳密に従った構造化データを出力します。生成結果のパース成功時に生成されたファイルのパスや、エラー時にはエラーメッセージと詳細情報が含まれます。

### 入力パラメータ

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| design_path | str | いいえ | design.json ファイルの直接のパス。省略された場合は name から自動探索します。 |
| name | str | いいえ | 対象の既存スキル名。design_path 省略時の自動探索キーとして使用されます。 |
| output_dir | str | いいえ | 生成されたSKILL.mdを保存するディレクトリのパス。省略時は対象スキルのディレクトリに出力されます。 |
| source_code_dir | str | いいえ | 実装ソースコードが格納されたディレクトリパス（または単一ファイル）。指定しない場合、自動的にスキルの scripts ディレクトリを探索します。 |

### 制約事項

- name と design_path のいずれか一方は必ず指定する必要があります。

### 実行例

#### 1. インプロセス呼び出し (推奨)
親エージェントが本スキルを動的ロードしてプログラムから起動する推奨コード例です。

```python
# 1. スキルのロード
skill = load_skill("skill-spec-writer")

# 2. 状態に引数を設定して実行
# ※ 引数は validated_input 経由で process_message に渡されます
# tool_context.state["validated_input"] = Input(...)
skill.process_message(tool_context)
```

#### 2. サブプロセス呼び出し (手動テスト用 CLI)
開発環境などで本スキルを手動で動作確認する際の起動コマンド例です。

```bash
python3 -m edd_agent_tools.cli.run --skill_name skill-spec-writer --name "target-skill-name"
```
