# skill-spec-writer

## 概要

設計定義ファイル（design.json）やソースコードをロード・解析し、ADK 2.0互換の仕様書（SKILL.md）を全自動生成するツール。

### 主な機能
* 設計情報（Pydanticスキーマなど）の動的なロードと解析。
* スキルの実行タイプ（tool/agent）に応じた仕様書生成ロジックの自動選択。
* LLMを活用したスキル概要、機能、トリガー条件、ワークフローなどの非決定論的テキスト情報の抽出。
* 入力パラメータ、出力パラメータ、制約事項を含むADK 2.0準拠のMarkdown形式SKILL.mdの生成。
* 指定されたディレクトリへの生成されたSKILL.mdファイルの保存。

### 内部処理の流れ
1. スキル名または設計ファイルのパスが提供されていることを検証します。
2. 指定されたスキル名またはパスに基づいて、対象スキルのディレクトリ構造と設計メタデータ（design.json）をロードします。
3. 出力ディレクトリとソースコードスキャン対象ディレクトリのパスを解決します（指定がない場合はデフォルト値を使用）。
4. スキルの実行タイプ（例: 'tool'）に応じて、適切な仕様書ライター（ToolSpecWriterなど）をファクトリパターンで構築します。
5. 構築されたライターを使用して、LLMへのプロンプトを生成し、必要に応じてソースコードディレクトリを添付します。
6. LLM（Gemini API）を呼び出し、スキルの目的、機能、トリガー条件、内部処理手順などの非決定論的テキスト情報を構造化JSON形式で抽出します。
7. 抽出された情報と設計パラメータ（入力/出力スキーマ、制約など）を組み合わせて、ADK 2.0準拠のMarkdown形式SKILL.mdコンテンツをレンダリングします。
8. 生成されたSKILL.mdファイルを指定された出力ディレクトリに保存し、その絶対パスを返します。

## トリガー条件

- 〇〇スキルの仕様書を生成して
- このスキルのSKILL.mdを作成してください
- 設計ファイルに基づいて仕様書を書き出して
- スキル〇〇のドキュメントを更新してほしい
- 指定されたソースコードからスキル仕様書を生成して
- ADK 2.0形式でスキル仕様書を作成してください

## AIエージェント向け使用方法

### 1. 実行手順（Instructions）

あなた（エージェント）がこのスキルをトリガーした場合は、以下の手順に従ってください。

1. 必要な入力パラメータ（`prompt`, `design_path`など）を決定します。
2. 決定したパラメータを指定して、このスキルを起動してください。
3. 実際の処理（API呼び出しやファイル出力など）は内部スクリプト側で完結するため、あなた自身が内部テンプレートを読み込んで推論したり、成果物を手動で組み立てたりする必要はありません。

> [!NOTE]
> **`prompt` パラメータの使用ガイドライン:**
> * **指定可能な指示**: 生成される仕様書のテキスト説明のトーンや粒度（例: 開発者向けに詳細に、あるいは初心者向けに簡単に書く）、特別に言及してほしいセキュリティ設計や注意点の強調を指定できます。
> * **構造的な制約（指定不可）**: 仕様書のマークダウンレイアウト構成（見出しの順序、テーブル項目）は決定論的テンプレートに固定されているため、プロンプト指示によって構成そのものを変更することはできません。


### 2. 呼び出し方法
- **インプロセス呼び出し (Python API)**: ロード関数 `process_message(params, tool_context)` を使用。
- **サブプロセス呼び出し (CLI)**: CLIランナーを使用。
  `python3 -m edd_agent_tools.run skill-spec-writer [オプション引数]`
- **出力形式 (Output Mode)**: `STRUCTURED_JSON` (特定のJSONスキーマ構造に厳密に従った構造化データを出力します。生成結果のパース成功時に生成されたファイルのパスや、エラー時にはエラーメッセージと詳細情報が含まれます。)

### 入力パラメータ

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| prompt | str | いいえ | 仕様書生成における、特別に明記したい追加の表現上のこだわりや注意点などの指示。 |
| design_path | str | いいえ | design.json ファイルの直接のパス。省略された場合は skill から自動探索します。 |
| skill | str | いいえ | 対象の既存スキル名。design_path 省略時の自動探索キーとして使用されます。 |
| output_dir | str | いいえ | 生成されたSKILL.mdを保存するディレクトリのパス。省略時は対象スキルのディレクトリに出力されます。 |
| source_code_dir | str | いいえ | 実装ソースコードが格納されたディレクトリパス（または単一ファイル）。指定しない場合、自動的にスキルの scripts ディレクトリを探索します。 |

### 出力パラメータ (構造化JSONの戻り値構造)

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| status | Literal['success', 'failed'] | はい | スキルの実行結果ステータス。'success' または 'failed'。 |
| message | str | はい | 実行結果に関する詳細メッセージ。 |
| output_file_path | str | いいえ | 生成されたSKILL.mdファイルの絶対パス。成功時にのみ存在し、失敗時はnull。 |

### 制約事項

- 'skill' または 'design_path' のいずれか一方は必須です。両方を省略することはできません。
