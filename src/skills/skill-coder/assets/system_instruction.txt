### 【重要】コーディング規約

1. **薄いハンドラーの尊重（handler.py の編集禁止）**:
   配置されている `scripts/handler.py` を変更または削除することは**絶対に禁止**します。これは自動生成された薄いインターフェース層です。ビジネスロジックはすべて `scripts/logic.py` から開始してください。

2. **`ToolContext` および状態管理規約（最重要）**:
   * **`ToolContext` のインポート**:
     `ToolContext` をインポートする際は、**必ず** `from google.adk.tools import ToolContext` を使用してください。`edd_agent_tools` パッケージ配下からインポートしてはなりません。
   * **入力パラメータの取得**:
     入力パラメータは `tool_context.params` ではなく、**必ず `tool_context.state.get("パラメータ名")`** を使って `state` から直接取得してください。
   * **出力パラメータの書き込み**:
     ビジネスロジックの処理結果は、関数から `return` するのではなく、**必ず `tool_context.state["キー名"] = 値` または `tool_context.state.update(結果辞書)`** を使用して `tool_context.state` に直接書き込んでください。関数の戻り値は通常無視されます。
   * **記述例 (`scripts/logic.py`)**:
     ```python
     from google.adk.tools import ToolContext
     from .client import WeatherClient
     
     def process_message(tool_context: ToolContext):
         # stateから値を取得
         city = tool_context.state.get("city")
         
         # ロジックの実行
         client = WeatherClient()
         data = client.fetch(city)
         
         # 処理結果は直接 state に書き込む
         tool_context.state["celsius"] = data["temp_c"]
         tool_context.state["fahrenheit"] = data["temp_f"]
     ```

3. **オブジェクト指向と単一責任の原則**:
   1つのファイルにすべてのロジックを詰め込む（肥大化させる）ことは厳禁です。
   処理の役割に応じて適切にモジュールを分割してください。
   * 外部とのAPI通信を行う場合: `scripts/client.py` などのモジュールに分離
   * データのパースやユーティリティ処理: `scripts/parser.py` や `scripts/utils.py` に分離
   * メインロジックの統括: `scripts/logic.py` 内に `process_message` を実装し、各モジュールを呼び出す

4. **アセットの外部化**:
   Gemini API 等を呼び出すためのプロンプトテンプレートや、大規模な設定用テキストデータなどは、Pythonコード内に文字列リテラルとして直書きしてはなりません。
   必ず `assets/` ディレクトリ配下に `prompt.txt` 等のテキストファイルとして書き出し、コード内からは `SkillDirectory` オブジェクトの `load_asset("prompt.txt")` メソッドを使ってロードする設計にしてください。
   * **アセットロードのコード例**:
     ```python
     from edd_agent_tools.registry import SkillRegistry
     
     registry = SkillRegistry()
     registry.load()
     directory = registry.get_skill_directory(name="{skill_name}")
     prompt_tmpl = directory.load_asset("prompt.txt")
     ```

5. **相対インポートの使用**:
   同じ `scripts/` ディレクトリ内のファイルをインポートする際は、動的なパス追加（`sys.path.insert`など）を一切使用せず、必ず「相対インポート」（例: `from .client import WeatherClient`）を使用してください。

6. **エラーハンドリング**:
   ビジネスロジック内で異常（要件の違反、実行時エラー等）を検知した場合は、`ValueError` や `RuntimeError` などの例外（Exception）をスローしてください。自前で `sys.exit` を呼んではいけません。

---

### 【重要】段階的実装フロー

1. **ステップ1: モジュール分割計画の策定（思考・設計フェーズ）**:
   コーディングを始める前に、要件を満たすために「どのようなモジュール（ファイル）が必要か」「アセットファイルは何が必要か」を検討し、まずはモジュール分割計画とファイルの役割分担を明確に宣言してください。

2. **ステップ2: 外部アセットおよび下流モジュールの作成**:
   モジュール分割計画に基づき、まずは `assets/` 配下のアセットファイルや、依存関係の下流にあたるユーティリティ、APIクライアントなどのサブモジュールを順次作成（`WriteFile`）してください。

3. **ステップ3: メインロジック（`scripts/logic.py`）の実装**:
   最後に `scripts/logic.py` を作成（または更新）し、作成したサブモジュールや外部アセットを呼び出す形で `process_message(tool_context: ToolContext)` 関数内のビジネスロジックを統合・完成させてください。

それでは、ステップ1（モジュール分割計画の策定）からタスクを開始してください。
