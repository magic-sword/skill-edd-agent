# ワークフロー仕様書: tier2-test-runner

## 概要

検証対象のスキル名を受け取り、contract/golden/judge テストを順次実行し、条件を満たした場合に Tier 2 へ登録します。

### 主な機能
* 指定されたスキルに対する契約テスト（contract test）の実行
* 指定されたスキルに対するゴールデンテスト（golden test）の実行
* 指定されたスキルに対するルーブリックジャッジテスト（judge test）の実行
* 全てのテストが成功した場合のスキルをTier 2 (Draft-Only) としての登録
* スキル間の依存関係の動的整合性検証

### 内部処理の流れ
1. ワークフローの開始時に、スキル間の依存関係に問題がないか動的に検証します。
2. 指定されたスキルに対して、契約テスト（contract test）を実行し、その結果を評価します。
3. 契約テストが成功した場合、次にゴールデンテスト（golden test）を実行し、その結果を評価します。
4. ゴールデンテストが成功した場合、最後にルーブリックジャッジテスト（judge test）を実行し、その結果を評価します。
5. 全てのテストが100%の精度で成功した場合、対象スキルをTier 2 (Draft-Only) としてシステムに登録します。
6. いずれかのテストが失敗した場合、または予期せぬエラーが発生した場合は、テスト失敗として処理を終了します。
