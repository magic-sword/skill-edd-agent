# ワークフロー仕様書: tier2-test-runner

## 概要

検証対象のスキル名を受け取り、contract/golden/judge テストを順次実行し、条件を満たした場合に Tier 2 へ登録します。

### 主な機能
* 指定されたスキルに対するContractテストの実行と結果評価
* 指定されたスキルに対するGoldenテストの実行と結果評価
* 指定されたスキルに対するJudgeテストの実行と結果評価
* 全てのテストが成功した場合のスキルTier 2 (Draft-Only) への自動昇格登録
* スキル依存関係の動的整合性検証（欠落・循環参照チェック）

### 内部処理の流れ
1. ステップ1: スキル依存関係の検証 - 対象スキルが依存する他のスキルが正しく定義されており、循環参照がないことを確認します。
2. ステップ2: Contractテストの実行 - スキルの契約（API仕様、型定義など）が正しく実装されているかを検証するテストを『test-generator』と『test-executor』スキルを連携して実行します。
3. ステップ3: Goldenテストの実行 - スキルの既知の入力に対する期待される出力が一致するかを検証するテストを『test-generator』と『test-executor』スキルを連携して実行します。
4. ステップ4: Judgeテストの実行 - スキルの振る舞いがルーブリック（評価基準）に沿っているかをLLMが評価するテストを『test-generator』と『test-executor』スキルを連携して実行します。
5. ステップ5: Tier 2 昇格処理 - 全てのテストが100%の精度で成功した場合、対象スキルを「Tier 2 (Draft-Only)」としてシステムに登録します。いずれかのテストが失敗した場合は、昇格処理は行われず、エラーが報告されます。

## 実行方法

このワークフローは、複数の処理ノードをパイプラインおよび動的分岐で実行する自律接続システムです。
以下の順番でステップが接続・順次実行されます：

1. **run-tier2-test** (function): contract, golden, judge テストを順次実行し、成功時に Tier 2 昇格処理を行います。

引数パラメータが入力されると、STARTノードから順に状態（tool_context.state）を伝播しながら処理が進みます。

## 出力仕様

*   **出力モード**: `STRUCTURED_JSON`
*   **詳細**: 特定のJSONスキーマ構造に厳密に従った構造化データを出力します。生成結果のパース成功時に生成されたファイルのパスや、エラー時にはエラーメッセージと詳細情報が含まれます。

### 出力パラメータ (構造化JSONの戻り値構造)

| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| status | Literal['success', 'failed'] | はい | 実行結果のステータス ('success' または 'failed') |
| message | str | はい | 実行結果の詳細メッセージ |
| registered | bool | はい | Tier 2 として登録が成功したかどうかの真偽値 |
